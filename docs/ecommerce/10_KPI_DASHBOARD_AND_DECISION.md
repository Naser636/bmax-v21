# KPI Dashboard & Decision Criteria — ODG_ECOMMERCE_OPPORTUNITY_TO_CASH_V1

KPIs are **empty until a Phase-2 pilot runs** — they are placeholders to be populated with *observed* data. No
value here is a result.

## KPI dashboard (populate with actuals)
| KPI | Definition | Target (central) | Red flag |
|---|---|---|---|
| Sell-through / month | units sold ÷ units available | ≥ 60% | < 40% |
| Contribution margin / unit | ASP − cost − fees − ship − returns − cotis | ≥ €2.4 | < €1.5 |
| Return rate | returns ÷ orders | ≤ 5% | > 10% |
| ACOS | ad spend ÷ ad-driven sales | ≤ 20% | > 35% |
| Sessions→unit conversion | units ÷ listing sessions | ≥ 8% | < 4% |
| Cash runway | reserve ÷ monthly net cash burn | ≥ 3 mo | < 1 mo |
| Dead-stock age | % stock > 90 days | ≤ 15% | > 30% |
| Reconciliation delta | model vs marketplace statement | ≈ 0 | unexplained gap |

## Decision gates (stop / correct / scale)
- **STOP** (exit the SKU/niche) if, after a real 6–8-week pilot: sell-through < 40% AND CM/unit < €1.5, or
  cumulative P&L tracking toward the prudent-scenario loss with no fixable cause. Liquidate stock, keep the
  reserve.
- **CORRECT** if one lever is off (ASP too low → reprice/bundle; returns high → fix listings/photos; ACOS high →
  cut ads, lean organic; a weak SKU → drop it). Re-run the model (`05`) on observed inputs.
- **SCALE** only if central-or-better is *observed* over ≥2 months (CM/unit ≥ €2.4, sell-through ≥ 60%, healthy
  reconciliation): add Cdiscount, widen SKUs, consider FBA for the hero SKU, then (only then) an owned shop.

## Honest framing
A green KPI board would show the activity *working*, not that it *was always going to*. **A structural/model
PASS is not market demand or profit.** Sales and profit remain unknown until an authorized, observed pilot.
