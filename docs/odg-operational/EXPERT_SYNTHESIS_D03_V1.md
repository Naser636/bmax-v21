## 4. ODG D03 synthesis — one coherent capability (not nine specialties)
**Thesis:** read the nine as one operating spine — *economics → threat model → inventory → policy → provenance → honest boundary*. **Retain:** Anderson (position by incentive — defensible auditor-ready evidence raw scanners don't produce); Schneier (state the threat model: CRA tech-doc + NIS2 vuln-handling + agentic ASI04, and explicit non-coverage); Springett (CycloneDX already emitted + **adopt SCVS as the external measurable-maturity yardstick**); Fox (license-policy as a consumption gate with empirical inventory); Cappos/Lorenc (keep the SLSA/in-toto *principle*; **adapt** — ODG uses symmetric keyed-HMAC not Sigstore keyless+log, and must say so honestly); Janca (Readiness Pack actionable by client devs + plain-language gap list). **Reject as in-scope capability (retain as honest hand-off/boundary):** Moussouris 29147/30111 (ODG does not operate a vuln-handling process — name it as the client's adjacent obligation); Zalewski (ODG does not fuzz/scan — the honest complement narrative).
**Conflicts:** harmonies Springett↔Fox + Cappos↔Lorenc reinforce the SBOM+provenance core; productive tension Zalewski/Moussouris (find & handle vulns) vs ODG evidence-only scope = the honest gap, surfaced never papered over; incentive caution (Lorenc/Fox/Springett-title/Janca carry vendor affiliations — weight framing as interested, cite standards/code over marketing).
**Reference architecture (real modules):** Inventory (Springett/Fox) → `sbom-audit-service` (CycloneDX, 8 ecosystems); Policy gate (Fox/SCVS) → `license-policy` (SPDX fail-closed); Provenance/attestation (Cappos/Lorenc) → `evidence-provenance` (in-toto/SLSA principle; keyed-HMAC pending); Evidence-chain integrity → audit-log keyed-HMAC + tip-anchor (#326); Untrusted-build isolation → bubblewrap; Agent-supply-chain (ASI04) → `third-party-agent-gate`; **Vuln finding/handling (Zalewski/Moussouris) → ABSENT, honest gap (no CVE scan, no 30111 intake).**
**Reusable external standards (map & cite, not re-license):** CycloneDX + VEX; OWASP SCVS; Dependency-Track; SLSA levels; in-toto/TUF; ISO/IEC 29147/30111.
**Failure modes & safeguards:** overclaim provenance (keyed-HMAC ≠ Sigstore transparency log) → assembler LIMITATION flags + explicit non-coverage; imply vuln coverage → forbidden, fail-closed declared-not-performed; certification confusion → "evidence/readiness prep, not certification"; vendor-framing bias → cite neutral standards over vendor collateral.
**Measurable criteria (SCVS-derived, ODG-honest):** SBOM completeness (components resolved/declared), license-decision coverage (explicit verdict; UNKNOWN never assumed safe), provenance stamp coverage (sourceCommit+sha256), reproducibility (byte-identical SBOM across two clean runs). **No vuln-detection metric claimed — that axis is empty by design.**
**Reproducible experiments:** (a) regenerate CycloneDX SBOM twice on same commit → byte-identical; (b) inject unknown-SPDX license → fail-closed flag (not silent pass); (c) regenerate across a release bump → diff + per-component verdict (D03-B); (d) tamper an evidence record → HMAC/tip-anchor rejects.
