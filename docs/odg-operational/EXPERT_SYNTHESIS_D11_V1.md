## 4. ODG D11 synthesis — one coherent capability ("Governed Conformance & Workflow-Integrity Verification", not nine specialties)
**No new primitive.** Explicit non-goals restated in every artifact: NOT an iPaaS (no connector marketplace, no live multi-system sync), NOT a registered PDP (no certified fiscal transmission), no live ERP/accounting connectors, no certification. The nine collapse into one model along **three ODG seams that already exist:**
1. **Document-conformance seam (rule-based) — EN 16931-core:** `einvoice-validator` (BR-CO-10/13/15, mandatory fields, duplicates, **exact integer minor-unit money, no float**), `einvoice-parser` (CII/UBL→neutral model, fail-closed), `einvoice-export` (emits CII/UBL **gated on validity**, **round-trip proof**), `factur-x-extract`. Grounding: Vernon (neutral model = canonical domain model), Erl (contracted self-contained capability), Hohpe/Woolf (Message Translator/Validator vocabulary).
2. **Process-conformance seam (behavioral) — the frontier van der Aalst opens:** `mission-*` + `campaign-controller` (dependency-aware selection, checkpoint/resume) + `audit-log` (keyed-HMAC) + `truth-lock`/`reality-gate`. Grounding: van der Aalst (conformance checking: does the *recorded process* conform to the *declared governed path*?), Ruecker (explicit inspectable compensable orchestration state), Richardson (saga/compensation for commercial steps).
3. **Commercial-integrity seam — honest state separation:** `commercial-pipeline`, `proposal-pipeline`, `quote`, `client-intake`, `pipeline-ledger`, `autonomous-commercial-cycle` (**prepared≠sent≠signed≠cashed**). Grounding: Richardson (each stage = compensable local transaction), Bogard (validate→authorize→audit as pipeline behaviors through GovernedExecutor), Newman (keep it one cohesive capability, don't distribute into connector sprawl).
**Retain:** van der Aalst conformance-measurement (fitness vs a reference model); Richardson saga/compensation + honest state transitions; Ruecker explicit-auditable-orchestration-state; Bogard mediator/pipeline-behavior cross-cuts; Hohpe EIP vocabulary; Vernon bounded-context/canonical-model; Erl standardized-contract + loose-coupling + fail-closed autonomy. **Adapt:** EIP messaging patterns as *descriptive vocabulary over in-process flows* NOT a broker runtime; BPMN orchestration discipline WITHOUT adopting a BPMN engine; mediator pattern *conceptually in TS* NOT MediatR (now-commercial .NET library — license-disclosed). **Reject:** classical SOA/ESB + WS-* heavyweight governance (Erl, superseded); any move toward live connectors/iPaaS marketplace (Newman's own warning); distributed 2PC (Richardson's whole point); download/sales popularity as a quality claim.
**ODG-specific improvements the experts do NOT themselves provide:** exact integer minor-unit money (eliminates float rounding in conformance arithmetic); round-trip conformance proof (export→re-parse→re-validate as positive interoperability evidence); honest stage separation (refuses to conflate prepared/sent/signed/cashed — most pipeline tooling over-claims "sent/done"); audit chaining (keyed-HMAC) + truth-lock (tamper-evident, provable process-conformance); fail-closed + enumerated supported-subset with gaps disclosed up front (core subset vs 900+ EN 16931 rules; no PDF/A-3 embedding; no certified transmission).
**Failure modes & safeguards:** over-claiming conformance → enumerated supported-subset + fail-closed refusal to emit from invalid data + "verification ≠ certification" per report; scope creep toward iPaaS/PDP → hard non-goals per artifact, external side-effects gated; process-conformance false confidence (clean log ≠ correct document) → the two seams are independent, behavioral conformance never substitutes for rule-based validity; dependency/licensing drift → borrow patterns not packages, disclose the MediatR/AutoMapper 2025 relicense; popularity-as-proof → matrix separates adoption signals from technical claims.

## 5. Benchmark/eval spec (conformance-to-standard, no superiority claim without head-to-head)
Baselines (external, named): EN 16931 (CEN) semantic model + official business rules; UN/CEFACT CII & OASIS UBL 2.1 schemas; Factur-X/ZUGFeRD; EIP catalog (vocabulary rubric); BPMN 2.0 (orchestration-correctness rubric); van der Aalst conformance metrics (fitness/precision) for process-conformance.
**Task A — document conformance (rule-based):** valid + deliberately-malformed CII/UBL/Factur-X (BR-CO violations, missing mandatory fields, duplicate invoice numbers, float-rounding traps). Metrics: violation-detection precision/recall vs the enumerated subset; **exact-money correctness (zero float drift)**; **round-trip integrity** (export→re-parse→re-validate equivalence rate); fail-closed rate on malformed input (target 100%). Limitation: measured only against ODG's *enumerated subset* (coverage %), never "EN 16931 compliant".
**Task B — process conformance (van der Aalst-style):** recorded mission-*/campaign-controller logs + injected deviations (skipped authorization, out-of-order stage, tampered audit entry). Metrics: fitness/precision vs declared governed reference path; deviation-detection rate; audit-chain tamper-detection (keyed-HMAC) = target 100%. Limitation: requires structured logs; path-conformance not legal/semantic correctness.
**Task C — commercial-stage integrity:** zero false stage-promotion (never "sent/signed/cashed" without the evidence token); compensation correctness on simulated rollback. Limitation: internal orchestration only; external send/transmit gated.
Reporting discipline: results as *conformance to the named external standard/rubric* w/ coverage % + disclosed gaps; **no comparative "beats MuleSoft/Camunda/a PDP" claim** unless a reproducible head-to-head w/ published methodology exists (none claimed).
