## 0. ODG reality grounding (verified in-repo, read-only)
`dataset-quality-service.ts` — ingests a REAL CSV/JSON/records dataset, computes REAL per-dimension metrics (completeness/validity/uniqueness/conformance vs declared schema); **fail-closed**: empty⇒`NO_DATA` (never fabricated 100), unparseable⇒`INVALID_INPUT`/`PARSE_ERROR`, unknown declared type carries no validity constraint; emits `{id,area,severity,detail,remediation,evidence}` (SARIF-emittable); pure/deterministic; supersedes old `score=100` stubs. ReDoS input-bound (lots #324): over-long cell treated NON-conforming before regex. `independent-label-policy.ts` — deny-by-default, ground-truth provenance must be independent of the evaluated system. `fairness-eval.ts` — group-level, ACCEPTED. `evidence-provenance.ts` — sha256 + source-commit binding (SLSA/in-toto/NIST SSDF PS.3 *principle*, not the heavyweight formats; keyed-HMAC hardening branch exists). **Match:** data-quality measurement + validation + provenance/integrity for AI-ready data (honest, fail-closed, per-issue remediation, tamper-evident). **Honest gaps:** NO ETL/pipeline, NO warehouse/lakehouse, NO catalog, NO live data-observability/lineage/alerting; internal/sandboxed modules, not a multi-tenant SaaS; `broad-it-independent-eval-set` needs an external labelled dataset. Does NOT compete with dbt (transform/orchestration) or Monte Carlo (live observability) as products — it is a point capability for evidence-based data-quality + provenance audits.

## 6. Procurement / trust / security / privacy (GDPR-heavy)
EU DQ procurement centers data residency/privacy: any tool touching personal data must satisfy GDPR (lawful basis, minimization, Art.32); provenance/lineage increasingly demanded. [FACT HIGH]. ODG trust posture [INFERENCE MED–HIGH]: pure/deterministic, no network/clock in the quality service, fail-closed, sandboxed, tamper-evident evidence ⇒ a **local/no-egress** quality audit is easier to procure than a cloud SaaS ingesting the data. Caveat [FACT HIGH]: ODG runs internally, no multi-tenant SaaS, **no SOC 2/ISO 27001 certification claimed** (mechanism ≠ satisfied ≠ certified) — a go-to-market gap, not a capability claim.

## 8. Gaps & differentiation
White space [INFERENCE MED]: (1) attestable fail-closed DQ for AI go/no-go gates (most tools *check* but can be configured to pass; few produce a tamper-evident provenance-bound attestation fit for an audit / AI-Act Art.10 evidence file); (2) local/no-egress quality audit for GDPR-sensitive data; (3) independent-label integrity (a system can't certify its own ground truth). ODG differentiation (real modules): honesty-by-construction (`NO_DATA` not fake 100), per-issue remediation, sha256+commit provenance, independent-label policy, ReDoS-bounded robustness, deterministic/offline. NOT differentiated on breadth.

## 9. Credible first offers (real modules only; no price)
1. **"AI-Ready Data Quality & Provenance Audit"** — ingest buyer CSV/JSON locally/sandboxed (no egress), run dataset-quality-service vs declared schema → fail-closed report (completeness/validity/uniqueness/conformance) + per-issue remediation + sha256/commit provenance stamp, framed as evidence toward an AI go/no-go gate or AI-Act Art.10 / GDPR accountability file (`dataset-quality-service.ts`+`evidence-provenance.ts`). 2. **"Independent eval-label integrity check"** (`independent-label-policy.ts`; honest: broad-it-independent-eval-set still needs an external labelled dataset). 3. **Fairness screen** on a supplied dataset (`fairness-eval.ts`). All three = audits/attestations, not a monitoring platform; complement (not replace) dbt/Soda/Monte Carlo/Collibra. No pricing proposed.
