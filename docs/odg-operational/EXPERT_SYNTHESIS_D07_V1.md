## 4. ODG D07 synthesis — one coherent capability (NOT nine specialties)
**Honest framing:** ODG is NOT an observability/APM product (no production telemetry ingestion, no agents/SDKs, no dashboards over customer prod, no alerting/on-call/paging). ODG's domain = **reliability-evidence assurance + SLO governance over its OWN mission ledger** — assurance, not telemetry. Experts mined for *methodology + integrity discipline*, not to clone products.
**The synthesised capability: a Reliability-Evidence Auditor/Governor** that (a) governs whether reliability claims may be asserted, (b) refuses to fabricate a green number, (c) prepares — never auto-applies — bounded responses.
**Mapping + retain/adapt/reject:** Beyer (documentation integrity) **RETAIN** → every slo-target carries CTO_PROVENANCE; Murphy+Rensin (availability-budget / operating model) **ADAPT** → slo-targets CONFIGURED→VALIDATED only on a provenanced baseline, else INSUFFICIENT_EVIDENCE; CRE provider↔consumer **ADAPT as aspiration only** (ODG flags customer-prod CRE as unbuilt; **reject any claim ODG already does it**); Allspaw (resilience/evidence-gated incidents) **RETAIN** → incident-recurrence + resolution-lifecycle (RESOLVED evidence-gated; security INCIDENT never averaged into a reliability rate — ODG's strongest alignment); Gregory (USE / baseline-before-claim) **ADAPT** → structured resource/error-first diagnostic checklist + "no baseline ⇒ no number" (latency SLOs `null`); Majors/Fong-Jones/Parker/Sridharan (telemetry/OTel/dashboards) **REJECT as product, RETAIN as thesis** → ODG doesn't build the telemetry/instrumentation/dashboard layer; retains their market consequence (collection commoditised by OTel/Prometheus ⇒ durable value is governance/assurance over standardised evidence).
**ODG improvements (more conservative than the external canon):** (1) survivorship-honesty — slo-collector refuses a tautological 100% denominator, marks `measurable:false` w/ reason; (2) PREPARE-not-APPLY — slo-response `autoApply:false` always; breaches produce bounded ordered recommendations for a separately-gated step; severity NONE<LOW<ELEVATED<CRITICAL, security INCIDENT strictly above reliability BREACH; (3) fail-visible health — odg-health reports UNKNOWN when a source is absent, never fabricates "healthy"; (4) crash-atomic evidence — checkpoint-engine crash-atomic + reboot-validated. No 10th primitive; aligns to expert-profile-assembler §302/§303 (authority = INTERSECTION; executes nothing).
**Failure modes & safeguards:** mis-positioning as a monitoring tool → capability description asserts the non-goals up front; fabricated green number under pressure → survivorship guard + INSUFFICIENT_EVIDENCE default + provenance requirement; ungoverned auto-remediation → autoApply:false invariant; security incident laundered into an availability average → separate FORBIDDEN_ACTION_BLOCK gate, CRITICAL path distinct; overclaiming customer-prod coverage → explicit "evidence is over ODG's OWN runs" limitation.
