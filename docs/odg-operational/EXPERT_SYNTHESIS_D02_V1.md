## 4. ODG D02 synthesis — one coherent capability (not nine specialties)
**Thesis:** a reasoning-and-acting agent loop (Yao) that only ever acts through a governed authority-bounded gate (Wooldridge semantics + ODG harness), measured with reproducible multi-metric evaluation (Liang), learning bounded few-shot adaptations (Finn/Levine), coordinating safely when multiple agents run (Stone), built from minimal reproducible data-disciplined engineering (Karpathy/Ng/Li). **Adopt:** ReAct loop; HELM eval doctrine; formal authority semantics; offline/bounded-RL caution; data-centric + minimal-reproducibility + benchmark rigor.
**Conflicts & resolution:** (1) capability vs governance — ReAct/ToT optimize unconstrained exploration; ODG requires every Act pre-authorized ⇒ wrap each Act in authorizeExecution, DENY/ESCALATE halts the loop (not "try anyway"). (2) autonomy vs evidence — RL/meta-learning reward raw success; ODG rewards *proven* success ⇒ ACCEPT only when evidence-provenance binds sourceCommit/sha256; green task ≠ proof. (3) multi-agent emergence vs isolation — Stone's open coordination can emerge; ODG requires cross-mission verdict isolation ⇒ sub-agents inherit only authority-intersection, no agent escalates another's scope.
**Retain:** ReAct loop, HELM eval, MAML-style bounded adaptation, formal authority semantics, offline-RL caution. **Adapt:** ToT → bounded branching under step/budget cap + per-branch authorization; SWE-agent → only inside ODG's confined write-set-limited executor; generalist-policy learning → crash-atomic learning-reuse store, never auto-applied without re-verification. **Reject (for D02 as shipped):** unconstrained open-ended autonomy; model training/pre-training (out of scope); any self-modifying agent touching constitution/authority (barred by §303).
**ODG improvement over the literature:** the literature optimizes capability + benchmark scores; ODG adds the missing layer — per-action authorization, evidence-bearing acceptance, authority intersection, fail-closed on cannot-verify, reproducible honest measurement. No new primitive.
**Reference architecture (real modules):** Perceive/Reason (Thought, no side effects) → Propose Act → **Govern** (third-party-agent-gate.evaluateAgentAction ADMIT|DENY|ESCALATE then agent-governance-harness.authorizeExecution/GovernedExecutor; runSequence halts on first non-ADMIT) → Execute (only ADMITted, confined, within write-set) → Observe→Evidence (evidence-provenance binds sourceCommit+sha256) → Checkpoint/Recover (crash-atomic learning store) → Orchestrate (campaign-controller dep-aware + cross-mission isolation) → Measure (autonomy-measure + Axe-B; honest NON-MEASURABLE allowed).
**Failure modes & safeguards:** act-without-authorization → authorizeExecution gate halts on DENY; scope/authority escalation → authority-intersection §307 + cannot_modify §303; unbounded exploration/cost → step+budget caps, ESCALATE on breach; fabricated/unverifiable success → evidence-provenance, cannot-verify ⇒ FAIL; prompt injection/tool abuse → OWASP Agentic Top-10 checks in the gate; stale/auto-applied learning → crash-atomic store + re-verify before reuse.
**Measurable acceptance criteria:** gate coverage = 100% of executed Acts (0 ungated); provenance completeness = 100% of ACCEPTED outputs (sourceCommit+sha256); fail-closed rate (every cannot-verify ⇒ FAIL/ESCALATE, 0 fail-open); authority-subset invariant (0 bound⊄mission); task metrics HELM-style (success/calibration/robustness/cost each w/ denominator+provenance).

## 5. Benchmark/eval spec
Tasks (ODG-native, confined): (a) multi-step engineering mission on a seeded repo (locate→patch-within-write-set→build→test→independently-verify), gated, mirroring SWE-bench/SWE-agent; (b) read-only investigation producing an evidence-bound report; (c) a tool-use chain requiring one ESCALATE (confirm the gate halts). External baselines (calibration, NOT superiority): ReAct on HotPotQA/WebShop, Tree-of-Thoughts, SWE-bench published numbers; HELM methodology. Metrics (HELM-style): task success; gate-coverage %; provenance-completeness %; fail-closed correctness; authority-subset violations (target 0); escalation precision/recall; cost/latency; reproducibility (identical gate decisions + hashes on re-run). Limitations up front: ODG runs confined/offline (no public TLS/billing/deploy); governance overhead *reduces* raw throughput vs ungoverned agents — that trade (safety+evidence for speed) is the design, not a defect; external baselines run in their own harnesses ⇒ not directly comparable, claim no superiority absent a controlled head-to-head.
