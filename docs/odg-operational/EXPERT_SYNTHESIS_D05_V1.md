## 4. ODG D05 synthesis — one coherent capability (evaluation-integrity, not nine specialties)
**Design axiom:** ODG's D05 = **an evaluation-integrity harness that refuses false success and refuses to judge its own labels** — experts mined for the disciplines that make such a harness honest; everything UI/e2e-automation-shaped stays out of the product. **Adopt:** Bolton checking-vs-testing → charter for `reality-gate` (a check ≠ verification; lower rung never implies higher); Adzic executable-spec/acceptance-on-agreed-criteria → `mechanical-acceptance` (acceptanceCriteria[] on FACTS not self-report; REJECT>BLOCKED>UNKNOWN>ACCEPT, deny-by-default); Kaner measurement-theory → honest denominators + NO_DATA headline + per-metric provenance; Hendrickson+Bach experiment/charter design → corpus authoring (every case a pre-registered charter w/ ground truth sealed; +/−/misleading controls in k-eval/broad-it-eval); Stewart standardization → sealed versioned hash-pinned corpora + argv-only confined execution; Crispin/Gregory quadrants → audit coverage-map; Jones architecture → flaky/maintainability critique in audits only.
**Conflicts & resolution:** Bach/Bolton "testing can't be automated" vs ODG automated evaluator → ODG **checks and labels itself a checker** (reality-gate never calls a check "verified"); Kaner/Bach reject single-number scoring vs ODG rates → `broad-it-eval` returns **NO_DATA** until an independent/representative/leakage-free corpus exists, `k-eval` scores only a sealed synthetic corpus and states it measures the pipeline not general capability; Adzic's cooperative ATDD assumes honest authors vs ODG assumes adversarial evaluees → `independent-label-policy` deny-by-default (no self-/evaluee-authored labels; DEV/HELDOUT disjoint by id AND content-sha256).
**Retain:** Bolton checking-vs-testing; Adzic executable-spec acceptance; Kaner "metrics mislead/no best practice"; Hendrickson charter case-design; Stewart reproducibility+standardization. **Adapt:** SBTM → session/charter provenance records on every verdict; Quadrants → audit coverage-map; Jones architecture → flaky/maintainability lens in audits only. **Reject:** any UI/e2e automation *product* (Stewart/Jones tool surface — dossier §3/§4); context-free "best-practice" certification (contra Kaner); self-authored ground truth or a single confident headline number without independent corpus; award/popularity as efficacy evidence.
**Reference architecture (real modules):** client evidence/claim → `independent-label-policy` (admission; no self-authored ground truth) → `broad-it-eval` (DEV/HELDOUT disjoint by id+sha256; NO_DATA until independent corpus) → `code-execution` (argv-only, bubblewrap-confined REAL compilers) → `mechanical-acceptance` (FACTS not claims) → `reality-gate` (ladder; check ≠ verified) → `k-eval` (sealed synthetic corpus, +/−/misleading controls) / `fairness-eval` (NO_DATA/NOT_APPLICABLE) → `expert-profile-assembler` (binds as capabilities/validators; authority = INTERSECTION). No 10th primitive — composition + intake adapters only.
**ODG improvements (no new primitive):** charter-record on every verdict (SBTM+provenance); executable-spec intake adapter (accept client Gherkin → mechanical-acceptance facts — monetizes the "evaluation-integrity audit" offer); coverage-map report (quadrants); adversarial "misleading-case" expansion (harden false-success resistance).
**Failure modes & safeguards:** green CI mistaken for verified → reality-gate (exitCode/reportOnly/mock never advance); evaluee grades itself → independent-label-policy deny-by-default; contamination/leakage → DEV/HELDOUT disjoint by id+content-sha256; overfit to visible cases → sealed HELDOUT never tunes + misleading control; confident number w/ no data → broad-it-eval NO_DATA, fairness NO_DATA/NOT_APPLICABLE; authority creep → assembler INTERSECTION + cannot_modify; award-as-proof → award ≠ contribution rule.
**Measurable criteria (for the synthesis):** 100% of method-poles traced to an existing module or explicitly REJECTED w/ reason (met); 0 new primitives (met); every expert claim carries source+date+confidence+verification status (met).

## 5. Benchmark/eval spec (false-success-resistant; no superiority claim)
Purpose: measure ODG's *evaluation-integrity* (resistance to false success + self-judging), NOT general IT testing capability (remains NO_DATA by design). Tasks (sealed corpus, extend k-eval/broad-it-eval): (1) **false-green trap** (green CI/exit-0 + seeded real defect → must NOT return ACCEPTANCE_VERIFIED); (2) **self-label trap** (evaluee supplies own labels → DENY); (3) **contamination trap** (HELDOUT case renamed into DEV → checkLeakage flags); (4) **misleading case** (superficial match contradicting criteria → REJECT/UNKNOWN); (5) **negative control** (clean repo → no findings); (6) **executable-spec acceptance** (partial Gherkin → correct deny-by-default). External baselines (comparison, not ranking): LangSmith, Braintrust, Arize/Phoenix, DeepEval — compare *integrity behaviors* (refuse self-judging? expose leakage? report NO_DATA?), not a leaderboard. Metrics: **false-success rate (target 0)** [headline]; self-judgment refusal (target 100%); leakage-detection recall (target 100%); negative-control false-positive (target 0); denominator honesty (numerator/denominator/provenance; BLOCKED/UNSUPPORTED excluded). Limitations up front: corpus SMALL+SYNTHETIC → measures pipeline integrity behavior not real-client/broad-IT capability; ground truth ODG-authored for synthetic set (proves the harness refuses dishonest inputs, NOT that ODG is "good at testing"); no superiority claim; honest headline remains NO_DATA for broad-IT efficacy.
