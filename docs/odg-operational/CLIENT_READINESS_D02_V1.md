## E. Discovery, intake & diagnostic process
Client supplies (read-only, no-egress where possible): their agent **contract** (objective, allowed tools, authorized scope, limits, require-human triggers), a trace/log of proposed actions, provenance descriptors for any ground-truth labels. Diagnostic: classify which action classes are gate-expressible vs `NO_DATA`; map the surface onto ASI01–ASI10; identify where the pipeline trusts an agent's self-report (a finding, not a pass). The gate is pure/deterministic/no-network/fail-closed — intake runs on client-supplied descriptors.

## F. Delivery methodology & technical architecture
D02 synthesis reference architecture → real modules: Perceive/Reason (no side effects) → Propose Act → **Govern** (`third-party-agent-gate.evaluateAgentAction`→ADMIT|DENY|ESCALATE deny-by-default, ASI01–ASI10 structural invariants not semantic intent; then `agent-governance-harness.authorizeExecution`/`createGovernedExecutor` — raw executor never called directly, a bare/unauthenticated ADMIT can never authorize execution; `runSequence` threads cumulative drift + halts on first non-ADMIT) → Execute (only ADMITted, confined, within write-set) → Observe→Evidence (executor result treated UNTRUSTED; independent verification required; `evidence-provenance.stampProvenance` binds sourceCommit + payload sha256 — SLSA/in-toto/SSDF binding *principle*, keyless byte-identical, optional keyed-HMAC) → Checkpoint/Recover (`checkpoint-engine`, `build-recovery-engine` — bounded self-repair reverting on non-decreasing error count, never a false success) → Measure (HELM-style multi-metric, honest NON-MEASURABLE allowed). **Wave-4 G-02 wired in:** `charter-record.makeCharter` binds each verdict to subject/method/groundTruth (omitted ⇒ `grounded:false` explicit, never a fabricated verified-against-truth), sealed via the evidence primitive — additive, verdict logic byte-unchanged.
