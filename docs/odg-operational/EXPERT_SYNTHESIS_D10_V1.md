## 4. ODG D10 synthesis — one coherent capability (honestly scoped)
**ODG D10 is NOT a FinOps platform. No new primitive.** The capability: **Observed-Usage Cost-Attribution Integrity** — "never report a cost you didn't observe; separate MEASURED from ESTIMATED; fail closed on the unmeasured; seal the provenance." It sits *beneath* the FinOps tools the experts build, not against them.
**Mapping to real modules:** deterministic value extraction → economic-extractor (OBSERVED/UNKNOWN, no AI/heuristic, refuses excess precision); per-engagement cost model → unit-economics (4 time buckets; per-field basis MEASURED|ESTIMATED; binding-constraint) — ODG's answer to Peterson's unit-economics thesis but refuses to fabricate the unit cost; integer-minor money → economic-unit (BigInt, no implicit math); observed-usage provider → OBSERVED-when-real/ABSENT-when-none; price resolution → price-resolution/cost-accounting (zero-rate catalog ⇒ PRICE_RULE_MISSING; no rate invented in-repo); allocation → resource-allocation-engine (deterministic, Local-First); verification → economic-verification (VERIFIED/INCOMPLETE/FAILED/UNKNOWN); null-honesty → campaign-metrics (unobservable ⇒ explicit null+reason).
**Retain:** Storment/Fuller FinOps vocabulary + lifecycle (speak the buyer's language); Peterson unit-economics concept (ODG's unit-economics.ts is a disciplined instance); Quinn skeptical read-the-bill posture (ODG's reason-for-being); FOCUS as the *input* format ODG consumes from client exports. **Adapt:** allocation (Advey) → deterministic resource-allocation-engine w/ provenance; governance (Bormann/Crowley) → ODG fail-closed/provenance-seal as an audit *control* not a dashboard; hybrid comparison (Lambert) → explicit MEASURED/ESTIMATED basis before any comparison. **Reject (out of scope by design):** live cloud-billing ingestion (CUR/Azure Cost Mgmt/GCP Billing); FOCUS *emission/ingestion* as a connector; optimization recommender (rightsizing/RI/savings-plan/anomaly); multi-cloud dashboard; %-of-spend pricing posture. ODG consumes client-*provided* exports only.
**ODG improvements over external frameworks:** (1) MEASURED-vs-ESTIMATED basis per field (most platforms present a single blended number); (2) fail-closed on unmeasured inputs (PRICE_RULE_MISSING, ABSENT, UNKNOWN != 0) vs platforms' silent estimates; (3) provenance seal (D2 keyed-HMAC audit-log + D4 economic-verification) — an audit-grade number, not a dashboard figure.
**Failure modes & safeguards:** category mismatch (buyers expect platform breadth) → reposition explicitly as integrity/audit layer; false precision/fabricated cost → economic-extractor refuses excess decimals, UNKNOWN != 0, no in-repo rates; silent zero → campaign-metrics explicit null+reason; scope creep into optimization → no recommender primitive, stop at the verified number.
**Measurable criteria:** fraction of output cost fields w/ explicit basis (target 100%); zero fabricated-cost incidents (any invented rate/currency = FAIL); provenance-seal verification rate (D4 ACCEPTED); UNKNOWN-vs-silent-zero audit (every unobservable = explicit null+reason).
**Reproducible experiments:** feed a client-exported FOCUS/CUR sample → every figure OBSERVED or UNKNOWN (no interpolation); inject a missing price rule → PRICE_RULE_MISSING (not €0); inject missing per-call tokens → ABSENT (not 0); re-run → identical provenance hash.

## 5. Benchmark/eval spec (cost-attribution integrity; no superiority claim)
