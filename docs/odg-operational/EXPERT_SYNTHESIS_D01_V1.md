## 1. Nine evidenced expert profiles (condensed; full sources §7)
1. **Martin Fowler** — Chief Scientist, Thoughtworks. Refactoring (behavior-preserving catalog), "code smells", "technical debt" metaphor, CI, enterprise app patterns. *Refactoring* (1999/2018), *PoEAA* (2002). Agile Manifesto signatory. Method: improve design in small reversible test-guarded steps; architecture emerges under CI+tests. Limit: self-described popularizer; "debt" over-stretched; presumes a test harness. [HIGH/VERIFIED]
2. **Kent Beck** — TDD, Extreme Programming, xUnit/JUnit (w/ Erich Gamma). *XP Explained* (1999/2004), *TDD by Example* (2003). Original Agile Manifesto signatory. Method: red-green-refactor; small steps localize failures; design grows from tests. Limit: TDD efficacy empirically contested; less suited to spikes. [HIGH/VERIFIED; JUnit co-authorship sub-claim PROVISIONAL]
3. **Robert C. Martin** — Object Mentor. SOLID (acronym coined by Feathers from his set), Clean Architecture (dependency rule), clean code. *Agile SD* (2002), *Clean Code* (2008), *Clean Architecture* (2017, ACM 10.5555/3175742). Method: depend on abstractions; isolate volatile detail behind stable boundaries. Limit: prescriptive heuristics not laws; over-indirection risk; some public opinions contested. [HIGH/VERIFIED; SOLID-acronym attribution PROVISIONAL]
4. **Michael Feathers** — legacy code = "code without tests"; **seams**; **characterization tests** (pin current behavior as a refactoring safety net). *Working Effectively with Legacy Code* (2004). Method: wrap risky code in tests recording what it *does now*, add seams, expand coverage outward. Limit: characterization tests can lock in bugs (pin behavior, not correctness); dated C++/Java examples. **Most direct map to ODG's legacy-modernization mandate.** [HIGH/VERIFIED]
5. **Dave Farley** — ex-Head of SW Dev, LMAX (Disruptor). Deployment pipeline, CD. *Continuous Delivery* (2010, w/ Humble), *Modern Software Engineering* (2021). Method: every change a release candidate through an automated staged pipeline; always releasable; deterministic build/test/deploy. Limit: needs test-automation + env parity; "inventor" framing = attribution. [HIGH/VERIFIED; Disruptor/award specifics PROVISIONAL]
6. **Jez Humble** — co-founder/ex-CTO DORA (Google 2018); UC Berkeley. CD + DORA four keys. *Continuous Delivery* (2010), *Lean Enterprise* (2014), *DevOps Handbook* (2016), *Accelerate* (2018). Method: automate the path to prod; decouple deploy from release; measure with evidence not opinion. Limit: Accelerate = self-reported survey (association not causation). [HIGH/VERIFIED]
7. **Gene Kim** — founder IT Revolution; ex-CTO Tripwire. "Three Ways" (flow/feedback/continual learning). *Phoenix Project* (2013), *DevOps Handbook*, *Accelerate*, *Unicorn Project*. Method: optimize the whole value stream; make work/bottlenecks visible; amplify feedback. Limit: *Phoenix Project* is didactic allegory (not evidence); Accelerate stats-lead is Forsgren. [HIGH/VERIFIED]
8. **Nicole Forsgren** — PhD MIS; founder/CEO DORA; GitHub/Microsoft Research/Google DevEx. Lead investigator of DORA four keys + lead author SPACE. *Accelerate* (2018, lead author), SPACE (2021). Method: define a metric's construct/denominator/source before measuring; pair speed with stability; publish limitations. Limit: survey-based, org-level not per-task. **Governs ODG's measurement integrity.** [HIGH/VERIFIED; no IEEE-award claim made — deliberately omitted as unverified]
9. **Mary Poppendieck** — lean→software: seven principles + seven wastes + 22 thinking tools. *Lean Software Development* (2003, w/ Tom Poppendieck), *Implementing/Leading Lean SD*. Method: eliminate waste (partial work, extra features, handoffs, delays, defects); decide at the last responsible moment; see the whole. Limit: mfg↔software analogy imperfect; "decide late" can become avoidance. [HIGH/VERIFIED]

## 4. ODG D01 synthesis — one coherent operating model
**Per-expert decision** (practice→decision→reflectedIn): refactor-under-test (Fowler) ADOPT→patch-executor+isolated workspace; execute-real-tests test-first (Beck) ADOPT→code-execution/validation-engine (never fakes a pass); isolate-detail-behind-boundaries (Martin) ADAPT→module-scoped fidelity gate; **characterization-baseline-before-legacy-edit (Feathers) ADOPT as new sub-pattern**→patch-executor+code-execution (ODG's strongest legacy lever, not yet a first-class step); deployment pipeline (Farley) ADAPT→CD flow minus public deploy (out-of-scope); automate+measure (Humble) ADAPT→campaign-controller per-mission (not org DORA survey); optimize-the-whole/flow (Kim) ADOPT→campaign-controller+dep-planner; construct-valid measurement (Forsgren) ADOPT→metrics carry definition/source/denominator/provenance, NO_DATA until representative; eliminate-waste/don't-redo-validated-work (Poppendieck) ADOPT→reuse-ledger+closure-register.
**Conflict resolution:** emergent design (Beck/Fowler) vs up-front boundaries (Martin) → test-guarded evolution *within* stable module boundaries; deliver-fast (Poppendieck/Farley) vs stability/measurement (Forsgren) → speed+stability are **paired gates**, neither alone = success (fidelity gate + independent verifier enforce); characterization tests can preserve bugs (Feathers) → label snapshots as *behavioral baselines* not correctness oracles, intended-behavior changes need explicit bless.
**Retain:** real-toolchain execution, isolated+rollback repair, characterization baselines, topological planning, construct-valid metrics, evidence reuse. **Adapt:** DORA (per-mission), CD (no public deploy), SOLID (guidance not gate). **Reject:** any DORA/SWE-bench *score* or "world-class" label ODG has not itself produced on a representative held-out run; award/popularity as proof of a technical property.
**Reference architecture (real modules):** Objective → dep-planner (topo layers, cycles fail-closed) → code-execution (real multi-lang checks) → patch-executor (isolated/confined/behavior-preserving; characterization baseline captured BEFORE edit) → build-recovery-engine (deterministic rebuild) → validation-engine + reality-gate (independent module-scoped fidelity) → broad-it-eval/eval-metrics (construct-valid) → closure-register + reuse-ledger → campaign-controller (flow/feedback/staleAcceptances fixpoint). Durable profile via `expert-profile-assembler` §302: capabilities=[code-execution, patch-executor, build-recovery-engine, validation-engine]; validators = sibling `.test.ts`; authority = INTERSECTION of mission authority and profile scope.
**Failure modes & safeguards:** fake/green-but-wrong pass → independent reality/fidelity gate ("cannot verify"=FAIL); characterization pins a bug → labeled behavioral-not-correctness + explicit bless; toolchain absent → UNSUPPORTED never PASS; metric gamed/over-claimed → speed+stability paired, NO_DATA until representative, no invented numbers; stale reuse → reuse-ledger freshness + dependency-change invalidation; scope/authority creep → assembler authority-intersection + §303 cannot_modify.
**Measurable criteria:** correctness (tests pass on independent re-run), reliability (reproducible across clean checkouts), quality (characterization diff = intended only), security (patch-executor confinement holds), efficiency (per-mission lead/recovery time, Forsgren-style). Each metric declares definition+denominator+source.

## 5. Benchmark/evaluation spec
Anti-overclaim principle: NO world-class/superior claim without a representative, leakage-guarded run ODG itself executed; report negative results. **Test tasks:** (1) legacy characterization + refactor (baseline-preserving refactor rate; bug-preservation flagged separately); (2) multi-language real-check with injected defects (true-positive rate vs UNSUPPORTED honesty; false-PASS must be 0); (3) build recovery (restore success + time-to-restore); (4) dependency planning (fail-closed on cycle); (5) independent-verification adversarial (reality-gate must REJECT a plausibly-wrong "validated" claim). **External baselines (reference only, not scored unless actually run):** SWE-bench / SWE-bench Verified; DORA four keys — used to define *what* to measure; `measuredSuccessRate = null` until ODG's own held-out run. **Metrics:** correctness/reliability/quality/security/efficiency. Disjoint dev/held-out by content sha256; publish failures + UNSUPPORTED counts + leakage detected.
