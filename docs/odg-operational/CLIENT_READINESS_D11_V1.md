## F. Delivery methodology & technical architecture
Three ODG seams that **already exist** (mapped to real modules; mechanism ≠ satisfied ≠ certified; no new primitive): **(1) Document-conformance seam (rule-based):** `einvoice-parser` (CII/UBL → neutral model via python3 stdlib, fail-closed on malformed) → `einvoice-validator` (BR-CO-10/13/15, mandatory fields, duplicates, **exact integer minor-unit money via economic-unit, `Number.isSafeInteger`, no float**) → `einvoice-export` (emits CII/UBL **gated on EN 16931-core validity**; `exportAndVerify` does model→XML→re-parse→re-validate; `roundTripEqual` true ONLY on mapped-field equality AND re-validation; XML-escaped, injection-safe) → `factur-x-extract` (PDF extract with bomb/stream caps + DTD-reject). Grounding: van der Aalst (conformance checking — the one academic anchor), Ruecker (explicit/auditable orchestration state), Richardson (saga/compensation). **(3) Commercial-integrity seam:** `commercial-pipeline`, `proposal-pipeline`, `quote`, `client-intake`, `pipeline-ledger`, `autonomous-commercial-cycle` — honest **prepared≠sent≠signed≠cashed**; promotion requires an evidence token.
