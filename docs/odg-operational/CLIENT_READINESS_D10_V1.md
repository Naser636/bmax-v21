## A. Professional identity & scope
A **cost-attribution-integrity service**: given economic/usage data a client has already exported, certify which figures are OBSERVED vs UNKNOWN, label every cost field MEASURED vs ESTIMATED, fail closed on anything unmeasured, seal the provenance — "never report a cost you didn't observe." IN: cost-attribution integrity audits on client-exported data; AI/LLM observed-usage unit economics; engagement/compute unit-economics readouts. OUT (NON_GOAL): no FinOps platform; **no live cloud-billing ingestion (not FOCUS/CUR/AWS-CUR/Azure-Cost-Mgmt/GCP-Billing-aware); no optimizer/recommender (rightsizing/RI/savings-plan/anomaly); no multi-cloud dashboard; internal-economics-only until a client supplies exports; %-of-spend pricing is explicitly not ODG's model.**

## C. Problems solved & measurable outcomes
"We can't prove what we actually spent on X"; "our AI/GPU inference cost is unpredictable and dominant"; "visibility ranked over optimization for AI spend — we want trustworthy numbers before recommendations"; "a blended platform figure hides what's measured vs estimated." Outcomes on the client's own exports: every output cost field carries an explicit basis (target 100%); zero fabricated-cost incidents (any invented rate/currency = FAIL); every unobservable value is an explicit null-with-reason not a silent zero; a re-runnable, provenance-sealed statement. ## D. Service catalogue & exclusions
(D10 dossier §9.) 1. **Cost-attribution integrity audit** — take the client's *already-exported* FOCUS/CUR/usage data (they hand it over; ODG does NOT connect to their cloud account), run `economic-extractor` + `unit-economics` → an audit-grade statement separating MEASURED vs ESTIMATED, flagging every unmeasured/fabricated-risk input, provenance-sealed. 2. **AI/LLM observed-usage unit economics** — provider observed-usage (OBSERVED-or-ABSENT, never fabricated) → honest per-workload LLM/inference unit economics with explicit UNKNOWN where the provider reports nothing. 3. **Engagement/compute unit-economics readout** — the measured `unit-economics` service (4-bucket time split; binding-constraint & capacity; honest net factor). Exclusions: no live cloud-billing connector; no optimizer/recommender; no multi-cloud dashboard; no FOCUS emission/ingestion as a product feature.

## E. Discovery, intake & diagnostic process
Client supplies (read-only, no-egress where possible): their exported cost/usage data (FOCUS 1.x / CUR sample, or provider usage records) + any declared price/rate rules. Diagnostic: classify what is reproducible as OBSERVED vs what must be declared UNKNOWN; identify every figure whose basis is ESTIMATED; surface any input with no price rule (→ `PRICE_RULE_MISSING`, never €0). ODG consumes **client-provided exports only** — it does not touch the client's cloud billing account.

## F. Delivery methodology & technical architecture
D10 synthesis (Observed-Usage Cost-Attribution Integrity) → real modules: deterministic value extraction → `runtime/core/economic-extractor.ts` (ACQUIRED bytes → OBSERVED value by a declared deterministic rule only — JSON-pointer/regex — no heuristic/AI/I-O, refuses excess decimal precision (`MAX_SCALE`), fail-closed OBSERVED/UNKNOWN); integer-minor money → `runtime/core/economic-unit.ts` (exact minor-unit quantities, no implicit math); per-engagement cost model → `runtime/core/unit-economics.ts` (4 time buckets, compute NOT free, per-field `basis: MEASURED|ESTIMATED`, capacity = binding constraint, warnings on unmeasured inputs — ODG's disciplined instance of Peterson's unit-economics thesis, refuses to fabricate the unit cost); observed provider usage → `src/tests/provider-observed-usage.test.ts` behaviour + `runtime/core/live-cost-metering.ts` (meters ONLY on a VALID declared budget, SPENDS only a REAL observation, OBSERVED-when-real/ABSENT-when-provider-reports-nothing; never fabricates cost/currency/token-to-money); price resolution → `runtime/core/price-resolution.ts` + `cost-accounting.ts` (missing rate ⇒ `PRICE_RULE_MISSING`; no rate invented in-repo); allocation → `src/runtime/vnext/resource-allocation-engine.ts` (deterministic, policy/constraint/strategy-aware, Local-First/offline option); verification → `runtime/core/economic-verification.ts` (VERIFIED/INCOMPLETE/FAILED/UNKNOWN); null-honesty → `runtime/core/campaign-metrics.ts` (unobservable ⇒ explicit `null`-with-reason). Mechanism ≠ satisfied ≠ certified; no new primitive (composition of the nine frozen primitives).
